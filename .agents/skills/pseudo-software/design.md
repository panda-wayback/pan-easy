# Pseudo Software — Design

## 前置

- 以 docs 节点为参考。

## 字段

| 字段 | 层级 | 内容 | 对应 `spec.yaml` 字段 | 必填 |
|---|---|---|---|---|
| 功能 | 能力 | 本能力做成什么样；复用 docs `目标` | 父级 `function` | 是 |
| 模块 | 能力 | 独立单元名称 | 父级 `modules` | 是，叶子写 `[]` |
| 输入 | 每模块 | 模块接收的数据/事件/上下文 | `input` | 是，无则 `[]` |
| 输出 | 每模块 | 模块返回的数据/事件/副作用 | `output` | 是，无则 `[]` |
| 模块契约 | 每模块 | 行为保证、边界条件、不变式 | `contract` | 是，非空 |
| 失败 | 每模块 | 错误码、触发条件、返回值 | `errors` | 推荐 |
| 依赖 | 每模块 | 依赖的其他模块或外部能力 | `depends` | 是，无则 `[]` |
| 测试 | 每模块 | 模块独立测试策略 | `tests` | 是，非空 |
| 组合测试 / Integration Test | 能力 | 组合验证；端到端关键路径 | 父级 `tests` | 有子模块时必填 |

## 拆分

- 一个模块 = 一个可独立理解、独立测试、有明确边界的责任单元。
- 模块须能一句话说清；说不清则再拆。
- 禁止为拆而拆。

## 草稿

在对话中给出，裁定前禁止写文件：

```markdown
### 功能

### 模块

| 模块 | 输入 | 输出 | 模块契约 | 失败 | 依赖 | 独立测试 |
|---|---|---|---|---|---|---|
| A | … | … | … | … | … | … |

### 组合测试

### Integration Test
```

## 裁定后

1. 按 `spec-yaml.md` 与 `templates/spec.yaml` 生成各模块 `spec.yaml`，登记父级 `modules`；父级 `tests` 写组合测试与 Integration Test。
2. 运行 `check_index.py`；失败须修复。
3. docs 节点 `解决步骤` 链接各模块 `spec.yaml`；模块拆分取舍写在链接旁一句，无则不写；禁止在 docs 复写契约。
4. 此后契约只以 `spec.yaml` 为准；docs 只在能力级目标/解决步骤变化时改。

## 禁止

- 写成代码说明书（函数级步骤、内部调用顺序）。
- 在本 Skill 写死本仓业务模块表或产品名词。
