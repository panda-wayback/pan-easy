# 下载空间控制

## 目标

限制单次分享下载的最大体积，并按「最近使用」清理冷文件，保证新任务有足够本地空间。

## 需求

### 单次大小上限（可配置）

- 服务对「一次分享任务」的文件总大小设硬上限；超过则拒绝，不转存、不下载、不扣费
- 上限可通过环境变量配置；默认 **10GB（1000 进制）**，与计费一致；**不允许关闭上限**（必须为正数）
- 管理端（`POST /api/tasks`）与 shop（`POST /tasks`）均生效
- shop 在预览得到总大小后、**核销卡密之前**即拒绝并提示
- 预览（只读查大小）不因超限失败，仍返回真实 `total_bytes`

### 按新任务腾空间

- 真正开始占用本地磁盘前（本地缓存未命中、即将下载），按**本任务需要的字节数**检查下载目录可用空间
- 空间不足时：先按「最久未使用」清理可删的冷交付物，再复查；清理后仍不足则任务失败并报错，不开始下载
- shop 在预览后、**核销卡密之前**调用主服务 `space-check`：清理后仍不足则直接失败（`disk_full`），**不扣次数**
- 本地缓存命中（不新占空间）时任务路径不做上述腾空间；shop 预检按预览总大小保守检查
- 「使用」刷新该交付物的最近使用时间（任一即算）：
  - 新任务本地缓存命中并复用该文件
  - 为该文件生成下载链接（含专属页「复制链接」/「下载文件」触发的生成）
  - 经 `/dl`（或 shop 转发）实际传输该文件
- 仅清理已交付物；**不删除**进行中任务的工作目录
- 删交付物后清理空的 `<总大小>/` 父目录；无对应运行中任务的残留空/脏工作目录一并扫掉
- 清理只删磁盘文件，不删任务历史；`saved_to` 已失效时按现有「文件被删」行为（下载 404 等）
- 另可定时做一轮「只清过期冷文件」的维护（不依赖新任务），间隔可配；真正为新任务腾空间发生在任务路径上

## 方案（已确认）

- 关系：建立在 [分享下载](../share-download/README.md) 的本地缓存与交付布局上；shop 见 [对外下载服务](../public-service/README.md)
- 修改：`app/tasks` — 总大小超限拒绝；下载前按任务大小检查可用空间 → 不够则清理冷文件 → 仍不够则失败；缓存命中与完成写入时刷新最近使用；定时维护扫描；扫掉空父目录与残留工作目录
- 修改：`app/api` — 透传配置；生成下载链接与 `/dl` 开始传输时刷新最近使用；暴露 `task_too_large` / `disk_full` 类错误
- 修改：`shop` — 预览后超限、或 space-check 空间不足时直接拒绝，不调 spark-auth、不扣次数、不创建任务；链接/下载走主服务已刷新逻辑
- 修改：根 `interface.yaml` — 登记环境变量；不引入与计费不一致的第二套进制
- 取舍：不为「固定留 N GB」设静态水位；空间是否够以**当前任务大小**为准
- 取舍：最近使用不用 atime（常见 `noatime`）；用显式更新 mtime 或旁侧元数据
- 取舍：清理单位是单个交付物，不整桶删 `<总大小>/`
- 取舍：「使用」= 任何会依赖该本地文件的服务行为（复用 / 发链 / 拉流），不要求用户一定下完；专属页有效期内点过链接的文件更不易被清，避免「刚复制链接就被清掉」
- 配置：
  - `BAIDU_EASY_MAX_TASK_GB`：单次任务最大总大小，单位 GB（1000 进制，支持小数）；填 `1` 即 1GB、`0.1` 即 100MB；默认 `10`；必须为正数
  - `BAIDU_EASY_CLEANUP_INTERVAL`：定时维护间隔秒数；默认 `3600`；`0` 表示关闭定时维护（按任务腾空间仍在）
  - `BAIDU_EASY_CLEANUP_MIN_AGE`：闲置超过该秒数才可被清理；默认 `604800`（7 天）

## 不做

- 不按用户/卡密做配额
- 不清理网盘侧「整理/」转存目录（仅本地 `/downloads`）
- 不做运营后台一键清空（若需要另开需求）
- 不引入与计费不一致的 GiB/第二套大小单位
