# 对外下载服务

## 目标

提供一个面向付费用户的独立下载网站：凭卡密粘贴百度网盘分享链接下载，用户接触不到管理页、主密钥与 baidu-easy 本身。

## 需求

- 网页任何人都能打开；没有可用的卡密时不能提交
- 卡密为 spark-auth 的按次数卡密，按分享文件总大小计费：每 `SHOP_BYTES_PER_USE` 字节扣 1 次（默认 300MB，1000 进制），不足按 1 次（默认粒度下下载 1GB 扣 4 次）；多文件分享按全部文件大小合计
- 提交时先只读查询分享信息得到文件总大小以确定扣费次数 N：链接失效、提取码错误等在这一步暴露，不扣次数、不创建任务
- 预览总大小超过 `BAIDU_EASY_MAX_TASK_BYTES`（默认 10GB，与主服务同一上限）时拒绝，不扣次数、不创建任务；详见 [下载空间控制](../download-space/README.md)
- 预览后检查下载目录空间（主服务先清理冷文件再判断）；仍不足时拒绝，不扣次数、不创建任务
- 再查卡密剩余次数；不足 N 时不扣费、不创建任务，提示充值后重新提交；够则一次性核销 N 次，成功后才创建下载任务
- 任务创建后下载失败、中断等异常不退还次数，由后台人工处理；程序内不提供自动退还或补偿
- 卡密记在本浏览器：提交成功（核销成功）后保存，下次打开首页自动填入，输入框始终以密码形式遮挡；卡密无效、次数已用完、不是按次数卡密、已停用时自动清除已保存的卡密
- 卡密输入框旁有「清除」按钮：清空输入框并删除本浏览器保存的卡密；输入框下提示「卡密保存在本浏览器，公共电脑用完请清除」
- 分享文字中没有百度网盘分享链接、或没填卡密时直接提示，不扣次数
- 卡密不可用时不创建任务，并按原因提示：卡密无效、次数已用完、不是按次数卡密、卡密已停用、卡密服务暂不可用
- 首页顶部有一个显眼、置顶（随滚动固定）且常驻的卡密组件：卡密输入框、提交与清除按钮，以及卡密使用情况都在同一块；输入卡密点「提交」后即看到剩余次数 / 总次数与已用次数，该组件常驻，刷新页面或跳转后仍在（卡密已存本浏览器）；成功后每 10 秒自动轮询刷新，清除或更换卡密时停止；失败（卡密无效、用完、不是按次数卡密、停用、服务不可用）在组件内提示
- 首页：粘贴分享文字（链接，可含提取码）后用独立的「提交下载」按钮提交，与卡密「提交」分开；提交成功后自动跳转到该任务的专属页面，任务大小与扣除次数在专属页面展示
- 专属页面：每次提交生成一个网址，打开无需输入任何信息；顶部同样有显眼的置顶组件，显示本任务的总大小与消耗次数，以及提交时卡密的剩余次数 / 总次数快照（不轮询、不实时查询）；页面显示文件标题、分享链接、状态、进度、速度、已下载/总大小、剩余时间、失败原因；未结束时自动刷新；完成的单文件任务（含多文件打成的 zip）有「下载文件」与「复制链接」；有返回首页的按钮，方便下次提交；不显示卡密
- 专属页面上任务失败或中断时显示「重试」与剩余重试次数：用原分享链接重新下载，不核销卡密、不扣次数；每个专属页面最多重试 3 次；重试后网址不变，页面继续显示新任务的进度与下载按钮
- 专属页面提交后 24 小时过期；重试不延长过期时间；在其中生成的下载链接不晚于页面过期
- 首页列出本浏览器提交过且未过期的专属页面（历史）；历史与专属页标题优先显示预览得到的文件名（单文件为全名，多文件为「首个文件名 等N个文件」），副行保留分享链接
- 用户看不到其他人的任务；baidu-easy 的管理页、`/api/*` 与主密钥对外不可见

## 方案

- 新增：`shop` 只读接口 `POST /card/status {code}`，转发 spark-auth `POST /api/redeem/status`，返回 `{remaining, used, uses}`（剩余 / 已用 / 总次数），错误码与提交时的卡密错误一致；不核销、不创建任务、不调用 baidu-easy
- 修改：`shop` `POST /tasks` 成功响应在 cost、remaining 之外增加 `uses`（提交时总次数快照），供专属页置顶组件展示
- 修改：`shop` 网页首页卡密区改为随滚动固定的置顶组件，「查询余额」与「提交下载」分开；查询成功后浏览器每 10 秒轮询 `POST /card/status` 刷新剩余/已用/总次数，清除或更换卡密时停止轮询
- 修改：专属页顶部新增置顶组件，从本浏览器历史读取该页记录，只显示本任务 cost 与提交时 remaining / uses 快照，不轮询
- 修改：Module `shop` 提交流程改为：baidu-easy 只读预览 → 算 N（ceil(总字节/SHOP_BYTES_PER_USE)，至少 1，默认 300_000_000）→ spark-auth `POST /api/redeem/status` 查剩余 → 不足则拒绝；够则 `POST /api/redeem {code, count:N}` 一次性扣 N 次 → 成功后才用主密钥创建下载任务；提交成功响应带 title（由预览文件名生成）
- 修改：`app/api` / `app/tasks` 分享预览只读接口返回 total_bytes 与 names（文件名列表）；shop 只调用该接口与既有任务接口
- 取舍：文件标题取自 preview（transfer list）而非解析分享文案：纯链接也能显示，且与真实分享内容一致；完成的单文件专属页标题仍可用 saved_to 最终文件名覆盖
- 复用：`app/api` 的 `POST /api/tasks`、`GET /api/tasks/{id}`、`POST /api/tasks/{id}/link`、`GET|HEAD /dl/{id}`、`POST /api/tasks/{id}/retry`
- 复用：spark-auth 的 `POST /api/redeem/status` 与带 `count` 的 `POST /api/redeem`（按其核销规范接入；扣减超过剩余会废卡，故先查再扣）
- 配置：`SPARK_AUTH_URL` 为 spark-auth 服务地址；本地调试时 shop 在容器内，填 `http://host.docker.internal:8000`
- 配置：`SHOP_BYTES_PER_USE` 为每 1 次扣费对应的字节数（1000 进制），默认 `300000000`（300MB），必须为正整数，否则 shop 拒绝启动
- 部署：容器内 8080 为管理页，compose 只绑定 `127.0.0.1:28080`；8081 为 shop，对外暴露 28081
- 取舍：shop 是独立进程而非在 baidu-easy 内加公开页，baidu-easy 代码保持不变，卡密、用户隔离都只改 shop
- 取舍：用按次数卡密而非设备激活卡密：网页读不到设备硬件标识，按次数不绑定设备，与「下载一次」的售卖方式一致
- 取舍：先只读预览再查余额再核销、核销成功才创建任务：文件大小决定扣费次数，预览还能让链接失效、提取码错误在扣费前暴露；预览用 transfer list 并递归展开分享内目录（--source-dir），避免只计顶层、目录内大文件漏扣；不占转存与下载名额
- 取舍：核销前先调 status 再 redeem(count=N)：spark-auth 在 count 超过剩余时会废卡，先查可避免误作废；status 与 redeem 之间仍有极小并发窗口，以 redeem 返回为准
- 取舍：按分享文件总大小计费，本地缓存命中、云盘去重免转存或任务重叠合并也照常扣费：费用对应「凭卡密拿到文件」，且这些短路同样消耗服务器查询与服务能力
- 取舍：任务创建后失败不退次数：核销成功即已使用；失败属运营异常，由后台人工处理，程序不自动退还
- 取舍：剩余次数随提交结果（含总次数快照）记在浏览器历史里，专属页面置顶组件从本浏览器历史读取，不轮询、不实时查；在别的浏览器打开专属页面时不显示
- 取舍：首页余额由浏览器持卡密每 10 秒轮询只读接口刷新；专属页无卡密，只展示提交时快照，避免为实时余额在服务器或网址中保存卡密
- 取舍：专属页面网址自带签名凭证（任务 ID + 过期时间），不需要存储；网址里不含卡密，转发网址不会泄露卡密
- 取舍：历史只保存在浏览器本地，不提供列出全部任务的接口
- 取舍：卡密存浏览器本地存储（关闭浏览器后仍在）而非只在当前标签页：用户每次来都不用重填；只在核销成功后保存，输错的卡密不会被记住；卡密仍只在提交时发给 shop，不出现在网址、专属页面与历史记录中
- 取舍：重试次数记在服务器端而非凭证里：凭证里的次数可以用旧网址绕过；重试只能重下同一个分享链接，所以不扣次数，用每页 3 次上限防止坏链接反复占用下载队列
- 取舍：所有失败都允许重试：bdpan 的错误码无法可靠区分提取码错误、链接失效与系统故障，由次数上限兜底
- 取舍：只提供手动重试，不自动重试：由用户判断是否值得再试，避免对失效链接自动重复下载

## 不做

- 设备激活卡密
- 跨设备同步历史
- 多文件打包下载
- 自动重试
- 任务失败后退还或补偿卡密次数（含自动与程序内人工入口；失败由后台线下处理）
