# 对外下载服务

## 目标

提供一个面向付费用户的独立下载网站：凭访问密钥粘贴百度网盘分享链接下载，用户接触不到管理页、主密钥与 baidu-easy 本身。

## 需求

- 网页任何人都能打开；未输入正确的访问密钥时不能提交
- 访问密钥每次提交时填写并由服务器校验，浏览器不保存
- 首页：输入访问密钥、粘贴分享文字（链接，可含提取码）提交；提交成功后跳转到该任务的专属页面
- 专属页面：每次提交生成一个网址，打开无需输入任何信息，显示分享链接、状态、进度、速度、已下载/总大小、剩余时间、失败原因；未结束时自动刷新；完成的单文件任务有「下载文件」与「复制链接」，多文件任务提示暂不支持；有返回首页的按钮，方便下次提交；不显示访问密钥
- 专属页面提交后 24 小时过期；在其中生成的下载链接不晚于页面过期
- 首页列出本浏览器提交过且未过期的专属页面（历史）
- 用户看不到其他人的任务；baidu-easy 的管理页、`/api/*` 与主密钥对外不可见

## 方案

- 新增：Module `shop`，独立服务（Python + FastAPI，独立镜像）：提供网页与任务接口，以访问密钥 `SHOP_ACCESS_KEY` 鉴权；服务器端用主密钥调用 baidu-easy
- 复用：`app/api` 的 `POST /api/tasks`、`GET /api/tasks`、`GET /api/tasks/{id}`、`POST /api/tasks/{id}/link`、`GET|HEAD /dl/{id}`
- 部署：compose 中 baidu-easy 端口只绑定 `127.0.0.1`，管理页只在服务器本机或 SSH 隧道访问；shop 对外暴露 28081，经内部网络访问 baidu-easy
- 取舍：独立服务而非在 baidu-easy 内加公开页或双端口，baidu-easy 保持不变，以后的卡密、用户隔离都只改 shop
- 取舍：访问密钥与主密钥分开，可单独更换，泄露不影响管理
- 取舍：专属页面网址自带签名凭证（任务 ID + 过期时间），不需要存储；网址里不含访问密钥，转发网址不会泄露密钥
- 取舍：历史只保存在浏览器本地，不提供列出全部任务的接口

## 不做

- 卡密激活（以后替换访问密钥）
- 跨设备同步历史
- 多文件打包下载
